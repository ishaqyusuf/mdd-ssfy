## Worker Usability Review

The recent table and Finance work is moving the product toward dense, scan-friendly operations screens. That fits office/admin and sales-manager usage better than older card-heavy flows.

The main trainability gap is trust boundaries and state names. A worker should not need to know which legacy route is safe, whether a scheduler button is production-affecting, or why a public filter route exposes internal choices. Scheduler, payment, inventory, office, and dispatch controls should have one visible owner, one permission rule, and one audit trail.

Mobile remains better on dispatch proof than prior runs because completion is now one resumable server operation. The remaining mobile concern is mixed reliability: invoice save parity is still not manually/device-proven, and job form debug logs indicate some flows still depend on developer observation instead of simple user-facing retry states.

## Customer And Dealer Experience Review

Dealer next-step guidance is now completed and visible across quote/order rows and detail surfaces, which helps dealers understand approval/payment/fulfillment state without calling the office.

Customer payment is still the biggest trust concern. Public tokenized checkout is expected, but the account-number pay portal returns broader context than a payment link should unless it is signed, time-bound, or authenticated. For customer trust, the self-service path should clearly separate: signed pay link, logged-in customer dashboard, staff-assisted terminal/wallet workflow, and dealer-managed customer payment.

Settings Active Sessions harms trust if exposed to real users because it implies security controls that do not exist. It should either become real session management or be hidden from non-admin/profile users until backed by actual session data.

## Door-Manufacturing Workflow Gaps

- Inventory release proof remains the key operational gate before production staff should trust the inventory-backed fulfillment model as the default. Door components, HPT/moulding/shelf/service projections, inbound demand, allocation, production readiness, and dispatch consumption all need clean reconciliation plus operator proof.
- Door/HPT/mobile parity is planned but not closed. Mobile still needs device proof that dimensions, supplier-sensitive pricing, LH/RH/no-handle/swing, grouped moulding/service rows, shelf items, and reopen/save behavior persist like web.
- Production readiness has improved after recent Sales Inventory work, but the cutover plan still requires browser/operator proof for configured-order blockers, safe continue, lifecycle sync, allocation dispatch, and delivery-quantity reconciliation.
- Dealer quote/request state guidance is completed, but dealer-facing fulfillment proof could become more concrete: pickup/delivery proof, production readiness, and expected handoff dates should be visible without leaking internal raw dispatch data.
