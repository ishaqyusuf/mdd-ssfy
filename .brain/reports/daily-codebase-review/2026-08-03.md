Inference: a caller who can reach the API can attempt background work outside a manager-approved operations surface, which creates accountability and production-risk problems for mixed-skill teams.

## Worker Usability Review

Dashboard and mobile workers need fewer ambiguous states around "can I act now?" The dealer approval flow and mobile dispatch proof flow are clearer than earlier reports, but task triggering, inventory readiness, and public read/report boundaries still make accountability hard to train. Warehouse and production workers need confidence that allocation, component history, and production readiness reflect real inventory state rather than a partially reconciled system.

The Active Sessions screen is especially risky for office/admin staff because it presents a familiar security-management pattern while using fake rows and fake logout. For mixed-skill teams, a non-functional security table is worse than no table because it trains users to trust a control that does not actually revoke anything.

Mobile reliability remains a practical field-work issue. Dispatch proof completion is now server-bound, but invoice save parity remains planned, and debug logs in mobile job form hooks suggest workflow plumbing still needs cleanup before it is comfortable for installers, drivers, and warehouse users.

## Customer And Dealer Experience Review

Dealer quote-to-order approval and next-step guidance have improved and are documented as complete. Evidence: the dealer router now hard-disables direct conversion and points dealers to office approval, while `apps/dealership/src/lib/dealer-next-step.ts` gives deterministic next-step text for request/order states.

Customer payment experience is still the main trust gap. The public pay portal returns enough customer/payment context that the safest customer-facing path should be a signed, short-lived, auditable link or authenticated customer session, especially before expanding online-paid follow-up or receipt resend workflows.

Customers and dealers would benefit from proof-oriented status updates that do not require calling a sales rep: approval requested, approved, paid, production ready, packed, dispatched, delivered/picked up, and proof uploaded. Dealer next-step guidance covers part of this for quotes/orders; the customer payment/fulfillment side still needs equivalent clarity.

## Door-Manufacturing Workflow Gaps

Production readiness still depends on clean inventory evidence. Door manufacturing creates high-cost mistakes when dimension, hinge, swing, profile, moulding, frame, glass, and hardware choices are approved without allocation visibility. The current Brain state says inventory correctness is not yet clean enough for release confidence.

The new sales form work is active in the dirty tree and is tracked in Brain, but broad browser replay was previously blocked by a local Next server issue. Until that path is re-proven end to end, quote clarity and production-readiness confidence should be treated as partially evidenced rather than settled.

The system should keep moving toward role-specific, trainable gates: sales can price and request approval; managers can approve exceptions; production can see what is buildable; warehouse can allocate/scan components; drivers/installers can provide photo/barcode proof; customers/dealers can see a clear, limited status timeline.

## Cross-Surface Consistency Gaps

- Dashboard/server task controls are improving through registry-backed task events, but mobile/API still have a generic public task trigger path.
- Dealer quote approval is now explicit, while customer payment/fulfillment status still lacks the same guided, proof-backed clarity.
- Office organization scoping has a plan, but the current API still lets public callers list/create organizations.
- Internal read/report routes have inconsistent protection compared with recently hardened mutations, which makes the permission story difficult to explain to managers.
- Active Sessions presents an admin workflow with production-like UI but non-production data and behavior.
- Inventory-backed fulfillment is a central manufacturing goal, but the system still has open evidence gaps before production/warehouse users can treat inventory allocation as authoritative.
