## Highest-Risk Findings

### P1 - Public Square Terminal Side-Effect Routes Remain Mounted

`apps/api/src/trpc/routers/square-test.route.ts:5` exposes a `squareTestRouter.test` mutation through `publicProcedure`, and the handler creates a Square terminal checkout with a caller-provided `deviceId`. `apps/api/src/trpc/routers/checkout.route.ts:43` also exposes `generateDeviceCode` through `publicProcedure`; `apps/api/src/db/queries/checkout.ts:1307` uses that path to create a Square Terminal API device code.

The tokenized checkout and quote-acceptance routes are intentionally public customer surfaces, but device pairing and test terminal side effects are staff/hardware operations. These should sit behind an authenticated staff boundary, a narrower role/permission, and a non-production/test guard where appropriate.

### P1 - Broad Typecheck Is Still Red

The broad validation gate is still failing in `@gnd/settings` because `packages/errors/src/index.ts` exports extensionless paths into NodeNext consumers. This appears mechanical and localized, but until it is fixed, broad CI-style confidence is degraded for any work touching shared settings, errors, contracts, or packages that consume them.

### P2 - Task Events Use Public Router Wrappers Around Inner Super Admin Guards

`apps/api/src/trpc/routers/task-events.route.ts:18` exposes `list`, `get`, `update`, `history`, `runNow`, `runTest`, and `runStatus` as `publicProcedure`. The query layer does call `requireSuperAdmin(ctx)` in `apps/api/src/db/queries/task-events.ts:16` before performing the operations, so this is not an observed unauthenticated execution bypass.

The risk is boundary consistency and future drift: job-control surfaces should advertise their access model at the tRPC boundary, matching the route-hardening direction already documented in Brain. A future helper added without the inner guard would inherit a public wrapper.

### P2 - Sales Lifecycle Cutover Is Blocked By Data Policy, Not Code Shape

The sales lifecycle cutover remains operationally blocked: the current Brain progress notes say the existing policy can handle 510 single-stage rows, but 658 cross-stage rows and order `09592DB` require an explicit user/product decision. Production remains at 5%.

This is the highest workflow blocker because repeated automation or script work cannot safely choose whether cross-stage sales should be completed, partially repaired, split, or left unresolved without changing business semantics.

### P2 - Active Sessions UI Still Uses Mock Device Data

`apps/dashboard/src/components/user-logged-in-devices.tsx:9` defines `mockDevices`, and `logOutDevice` at `apps/dashboard/src/components/user-logged-in-devices.tsx:35` only waits and contains a TODO for actual logout logic. The table renders the mock data at `apps/dashboard/src/components/user-logged-in-devices.tsx:47`.

For a settings/security surface, fake sessions and fake revocation can mislead staff or customers into believing account access has been controlled when no token/session revocation happened.

## Worker Usability Review

### P2 - Mobile Packing Quantity Drafts Are Not Durable

`apps/mobile/src/features/dispatch/components/dispatch-detail-screen/hooks/use-packing-slip-drafts.ts:32` stores packing quantities in React state and resets draft values from `packableItems` when the packing sheet opens. This is ergonomic for a short uninterrupted session, but warehouse and delivery work often happens under app switching, weak network, scans, calls, and device sleep.

The invoice flow has moved toward local recovery patterns elsewhere in the mobile app. Packing slip quantities should get the same recoverable draft treatment before relying on the mobile funnel for high-volume physical work.

### P3 - Driver Platform Closeout Still Needs Field-Proof Evidence

The Driver Platform Revival map records the core revival work, but closeout evidence is still the important remaining gate: selected employee authentication, mixed legacy/inventory packing sequencing, start/proof completion, failure/reconciliation, and pilot handoff need real device or pilot evidence before broad rollout.
