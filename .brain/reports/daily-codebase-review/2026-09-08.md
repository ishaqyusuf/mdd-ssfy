## Highest-Risk Findings

### P1 - Legacy Sales Router Still Exposes Internal Writes As Public Procedures

`apps/api/src/trpc/routers/sales.route.ts:1874` exposes `salesPayWithWallet` as `publicProcedure`; it applies wallet funds to selected sales IDs and then reconciles Sales Handoff. `apps/api/src/trpc/routers/sales.route.ts:1896` exposes `restore` as `publicProcedure` and directly clears `deletedAt` on a Sales order. `apps/api/src/trpc/routers/sales.route.ts:1942`, `apps/api/src/trpc/routers/sales.route.ts:1947`, and `apps/api/src/trpc/routers/sales.route.ts:1952` expose supplier save/delete and step metadata mutation through public wrappers.

For a door manufacturer, these paths touch money, order visibility, supplier/catalog pricing, and workflow structure. They should be protected by authenticated route boundaries and explicit permissions, not only by UI reachability or caller discipline.

### P1 - Square Terminal Device And Test Routes Remain Public

`apps/api/src/trpc/routers/checkout.route.ts:43` exposes `generateDeviceCode` as a public mutation, and `apps/api/src/db/queries/checkout.ts:1317` creates a Square Terminal API device code with a fixed terminal name. `apps/api/src/trpc/routers/square-test.route.ts:5` exposes `squareTestRouter.test` as `publicProcedure`, and `apps/api/src/trpc/routers/square-test.route.ts:16` creates a Square terminal checkout for a caller-provided device ID.

Signed customer checkout links are valid public surfaces. Staff hardware pairing, device-code creation, and test terminal charges are not. Those should be staff-authenticated, permissioned, and environment-gated or unmounted outside local development.

### P1 - Broad Typecheck Is Still Red

The broad typecheck continues to fail in `@gnd/settings` because `packages/errors/src/index.ts` uses extensionless relative exports under a NodeNext consumer. The issue is localized and mechanical, but it keeps the broad validation signal red across settings, errors, API contracts, and shared package consumption.

### P2 - Task Events Still Advertise Public Router Boundaries

`apps/api/src/trpc/routers/task-events.route.ts:18` builds the router with public procedures; list/get/update/history/runNow/runTest/runStatus are public wrappers at `apps/api/src/trpc/routers/task-events.route.ts:21`, `apps/api/src/trpc/routers/task-events.route.ts:26`, `apps/api/src/trpc/routers/task-events.route.ts:31`, `apps/api/src/trpc/routers/task-events.route.ts:42`, `apps/api/src/trpc/routers/task-events.route.ts:53`, `apps/api/src/trpc/routers/task-events.route.ts:58`, and `apps/api/src/trpc/routers/task-events.route.ts:67`.

The query layer currently calls `requireSuperAdmin` in `apps/api/src/db/queries/task-events.ts:16`, so I did not find an unauthenticated static bypass. The remaining risk is boundary drift: job-control routes should declare their access model at the tRPC boundary so future helpers do not accidentally inherit a public wrapper.

### P2 - Account Security Still Shows Mock Active Sessions

`apps/dashboard/src/components/user-logged-in-devices.tsx:9` defines hard-coded `mockDevices`, and `apps/dashboard/src/components/user-logged-in-devices.tsx:38` leaves logout as `TODO: Implement actual logout logic.` The route/table migration made the UI more polished, but the security control is still not real. That can mislead office/admin users during lost-device, suspicious-login, or employee-exit situations.

### P2 - Mobile Packing Drafts Are Still Not Interruption-Safe Until Submitted

`apps/mobile/src/features/dispatch/components/dispatch-detail-screen/hooks/use-packing-slip-drafts.ts:32` stores packing quantities in React state, and `apps/mobile/src/features/dispatch/components/dispatch-detail-screen/hooks/use-packing-slip-drafts.ts:36` reinitializes from current packable items when the sheet opens. `apps/mobile/src/features/dispatch/components/dispatch-detail-screen/index.tsx:904` can save the current packing slip to the server, but partially entered quantities before that action do not mirror the delivery-proof draft recovery model.

This matters in warehouse and route work because app switching, weak signal, device sleep, scanning, and customer interruptions are normal. Unsaved packing quantities should either recover locally or be clearly treated as transient input.
