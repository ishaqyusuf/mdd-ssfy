## Highest-Risk Findings

### P1 - Legacy Sales Router Still Exposes Internal Writes As Public Procedures

`apps/api/src/trpc/routers/sales.route.ts:1856` exposes `salesPayWithWallet` as `publicProcedure`; it applies wallet funds to arbitrary `salesIds` through `packages/sales/src/wallet.ts:58` without an evident route-level auth guard. `apps/api/src/trpc/routers/sales.route.ts:1878` exposes `restore` as `publicProcedure` and directly clears `deletedAt` on a Sales order. `apps/api/src/trpc/routers/sales.route.ts:1924`, `apps/api/src/trpc/routers/sales.route.ts:1929`, and `apps/api/src/trpc/routers/sales.route.ts:1934` expose supplier save/delete/step-meta mutations as public wrappers; the underlying functions in `apps/api/src/db/queries/sales-form.ts:46`, `apps/api/src/db/queries/sales-form.ts:121`, and `apps/api/src/db/queries/sales-form.ts:150` perform writes and cache/task invalidation without an immediate permission check in those functions.

This is sharper than the task-event wrapper issue because these are older operational write paths, not just public wrappers around a visible inner Super Admin guard. For a door manufacturer, supplier catalog edits, sales restore, wallet application, and sales workflow metadata directly affect pricing, order state, inventory sync, and customer money. These should be moved behind protected procedures plus explicit permissions before broad rollout claims.

### P1 - Public Square Terminal Side-Effect Routes Remain Mounted

`apps/api/src/trpc/routers/square-test.route.ts:5` exposes `squareTestRouter.test` through `publicProcedure`, and `apps/api/src/trpc/routers/square-test.route.ts:16` creates a Square terminal checkout with a caller-provided `deviceId`. `apps/api/src/trpc/routers/checkout.route.ts:43` exposes `generateDeviceCode` through `publicProcedure`.

Tokenized checkout and quote acceptance can be legitimate public/customer flows, but physical terminal checkout creation and device-code pairing are staff/hardware operations. They should require authenticated staff context, a narrow permission, and environment/test-mode gating.

### P1 - Broad Typecheck Is Still Red

`packages/errors/src/index.ts:1` through `packages/errors/src/index.ts:21` still export extensionless relative paths into a NodeNext consumer, causing `@gnd/settings` typecheck failure. The current failure is mechanical and localized, but it keeps the broad validation gate red and makes it harder to trust unrelated work touching settings, errors, API contracts, or shared package imports.

### P2 - Task Events Still Use Public Router Wrappers Around Inner Super Admin Guards

`apps/api/src/trpc/routers/task-events.route.ts:18` exposes task-event list/get/update/history/run operations through `publicProcedure`. The query layer does call `requireSuperAdmin(ctx)` in `apps/api/src/db/queries/task-events.ts:16`, so I did not find an unauthenticated execution bypass in this static read.

The risk is boundary drift: job-control routes should advertise the access model at the tRPC boundary. A future helper added without the inner guard would inherit the public wrapper.

### P2 - Account Security UI Still Shows Mock Active Sessions

`apps/dashboard/src/components/user-logged-in-devices.tsx:9` defines `mockDevices`, and `apps/dashboard/src/components/user-logged-in-devices.tsx:35` only simulates logout with a timeout before a TODO. For settings/security, fake active sessions and fake revocation can mislead staff or customers into thinking account access has been controlled.

### P2 - Mobile Packing Quantity Drafts Are Still Volatile

`apps/mobile/src/features/dispatch/components/dispatch-detail-screen/hooks/use-packing-slip-drafts.ts:32` stores packing quantities in React state, and `apps/mobile/src/features/dispatch/components/dispatch-detail-screen/hooks/use-packing-slip-drafts.ts:36` reinitializes the draft from current packable items whenever the sheet opens. The mobile proof flow has durable AsyncStorage/FileSystem draft recovery elsewhere, but packing quantities do not yet share that interruption-safe model.

In warehouse and delivery work, app switching, device sleep, weak signal, scans, and customer calls are normal. Losing partially entered quantities creates rework and can lead to inaccurate load/dispatch state.
