# Prototype The Connected Admin And Driver Flow

Type: prototype
Status: open
Blocked by: 07, 08, 09
Parent: [`../map.md`](../map.md)

## Question

Does one low-cost connected prototype make the complete critical path obvious
to both office admin and driver: assign order, open assigned work, verify and
reduce quantities, request permission, approve or deny, finish packing, start
delivery, capture signature/proof, and observe fulfillment? Prototype the
desktop admin and narrow responsive driver states with realistic dense data,
then record the human feedback and interaction decisions required by the final
specification.

The prototype is a decision artifact, not production code, and must expose
blocked, denied, partial, retry, and success states rather than only a happy
path.
