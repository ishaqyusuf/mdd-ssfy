# Define The Admin Command Center

Type: grilling
Status: open
Blocked by: 05, 06
Parent: [`../map.md`](../map.md)

## Question

What information architecture lets office admins oversee orders, assigned and
available drivers, outgoing activity, lifecycle status, packing progress,
approval requests, exceptions, and fulfillment without duplicating several
mini-apps? Define the primary sections, operational summaries, default table
columns, attention queues, detail-sheet tabs, driver activity view, filters,
bulk actions, and the single most important next action for each lifecycle
stage.

The answer should adapt the existing six-section Dispatch Admin workspace and
Sales Finance shell rather than assuming every current section survives
unchanged.

## Comments

> *This was generated by AI during Wayfinder issue commenting.*

**Proposed answer:** Make the canonical Fulfillment list one row per Sales
Order/fulfillment demand, not one row per dispatch. Default columns should be
Date, Order, Ship To, Assigned To, Status, exception badges, and Actions. Remove
the Progress column; detailed requested/packed/delivered/remaining quantities
belong in the order's Dispatch tab.

Clicking a row should open Sales Overview on Dispatch, not Packing. The Dispatch
tab should show the order-level fulfillment summary and a chronological list of
created dispatches. Its primary action is `Create dispatch` only when remaining
eligible quantity exists and no conflicting active allocation prevents it.
Clicking a dispatch opens dispatch detail with Overview, Items & Packing,
Route, Proof, and Activity; `Open packing workspace` is an explicit contextual
action.

Rename a Queue metric to Assigned only when it counts rows with an assignee;
otherwise keep separate `Needs assignment` and `Assigned` cohorts. An order with
multiple active dispatches should show a compact aggregate such as `2
dispatches` rather than implying a single assignee.

**Why:** The list answers where each order is in its lifecycle, while the sheet
owns the one-to-many dispatch workflow and the admin's next action.
