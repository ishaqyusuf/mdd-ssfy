# Define Compatibility, Cutover, And Rollback

Type: grilling
Status: open
Blocked by: 10
Parent: [`../map.md`](../map.md)

## Question

How should the approved responsive flow coexist with and eventually replace or
retain the current Dispatch Admin implementation, `/sales/packing-list`,
`/sales-book/dispatch-task`, and Expo driver experience? Define reused domain
commands, URL/deep-link compatibility, role rollout, pilot cohort, data or
schema needs, telemetry, acceptance evidence, rollback conditions, and the
explicit decision required before any old surface is removed.

The answer must reconcile this map with the existing Driver Platform Revival
Closeout rather than allowing two conflicting cutover programs to proceed.
