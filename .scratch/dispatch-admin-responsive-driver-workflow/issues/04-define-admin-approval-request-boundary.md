# Define The Admin Approval Request Boundary

Type: grilling
Status: open
Blocked by: 03
Parent: [`../map.md`](../map.md)

## Question

Which blocker classes can generate a driver permission request, and what does
approval actually do for each class? Distinguish at least missing production
assignment, completed-but-unsubmitted production, pending material review,
open inbound work, missing inventory configuration, genuine physical shortage,
Special Order enforcement, and stale revisions. Define required admin
capabilities, review evidence, reason, expiry, idempotency, approve/deny
outcomes, and what must remain impossible to bypass.

The answer should reuse canonical receive/manual-fulfillment/production-review
or revision-bound override commands where applicable. A generic status rewrite
or blanket skip is not an acceptable resolution.

## Comments

> *This was generated by AI during Wayfinder issue commenting.*

**Proposed answer:** Let a driver request assistance for every blocker, but
permit an override only for an explicitly allow-listed, revision-bound blocker
class. Bind each request to the dispatch, item/allocation, blocker class,
manifest revision, reporter, and idempotent request identity.

- Missing production assignment: assign production; approval does not fabricate
  production.
- Completed-but-unsubmitted production: use the canonical protected production
  review/submission command.
- Pending material review: resolve the material review before packing.
- Open inbound work: receive or reconcile through the canonical inbound/manual
  fulfillment workflow.
- Missing inventory configuration: route to an authorized inventory correction;
  do not assume stock exists.
- Genuine physical shortage: reduce the current dispatch, preserve back-order
  demand, or reschedule; never override physical availability.
- Special Order enforcement: use only its existing permissioned,
  revision-bound override with required reason/evidence.
- Stale revision: reload and revalidate; stale manifests are never approvable.

Require the capability belonging to the responsible domain rather than one
blanket dispatch-admin permission. Approval or denial records actor, evidence,
reason, timestamp, and resulting command. A permitted exceptional approval
expires when the manifest, allocation, order, or driver assignment revision
changes. Retries with the same identity return the prior result.

**Why:** Admin intervention resolves a specific operational cause without
turning approval into a generic safety bypass.

**Assumptions / risk:** The exact existing capability names must be mapped
during specification; introducing one broad override permission would weaken
the production, inventory, and Special Order boundaries.
