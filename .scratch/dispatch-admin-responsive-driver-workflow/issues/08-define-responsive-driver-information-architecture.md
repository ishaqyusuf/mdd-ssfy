# Define The Responsive Driver Information Architecture

Type: grilling
Status: open
Blocked by: 01, 05, 06
Parent: [`../map.md`](../map.md)

## Question

What phone-first responsive information architecture gives the driver a clear
assigned-work dashboard, warehouse packing journey, permission-request state,
ready-to-move queue, ongoing delivery, destination details, proof capture, and
completed history? Define navigation, next-action hierarchy, list/card detail,
touch and viewport constraints, error/retry states, and how the same pages
adapt to tablet and desktop without exposing admin-only controls.

The answer should preserve the useful behavior already present in the mobile
driver flow while removing mobile-only assumptions.
