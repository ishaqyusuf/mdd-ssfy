# Define Payment Qualification Semantics

Type: grilling
Status: open
Blocked by: None
Parent: [`../map.md`](../map.md)

## Question

How does each Sales Handoff Trigger option qualify an order using canonical
payment truth? Define `Fully paid`, `Any payment received`, and `Payment
percentage reached` across partial and grouped payments, refunds, wallet credit,
pending or failed provider activity, zero-total and COD orders, order
cancellation, payment reversals, and later changes to the global setting.

Also define percentage rounding, valid configuration bounds, the New York
business-time boundary if one is needed, and whether changing the setting
re-evaluates existing active orders immediately.

## Comments

> *This was generated by AI during Wayfinder issue commenting.*

**Proposed answer:** Evaluate active, non-cancelled orders using the canonical
cents-based settlement projection:

- `Fully paid`: positive invoice total with net amount due at or below zero.
- `Any payment received`: successful net receipts greater than zero.
- `Payment percentage reached`: successful net receipts divided by invoice
  total meets a configured whole-number threshold from 1–100%.
- Completed refunds reduce net receipts; pending, failed, deleted, and reversed
  payments do not qualify.
- Applied wallet funds count only when represented as a completed order receipt.
- Zero-total and COD orders do not qualify through payment; they require a
  separately defined operational-release policy.
- Setting changes immediately re-evaluate active orders, but newly exposed
  actions start their escalation clock when the changed policy takes effect
  rather than generating retroactive manager escalations.
- Payment qualification uses integer cents and does not require a business-time
  boundary.

**Why:** This reuses the existing settlement truth, handles refunds
consistently, and prevents setting changes from flooding managers with old
escalations.

**Assumptions / risk:** COD and zero-total operational release remain outside
this feature. Percentage thresholds are whole numbers unless finer precision
becomes a demonstrated need.
