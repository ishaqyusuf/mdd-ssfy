# Define The Sales Alert Projection And Access Scope

Type: grilling
Status: open
Blocked by: 01, 02, 03
Parent: [`../map.md`](../map.md)

## Question

What bounded read model should power `Paid sales need action` without slowing
the Sales Orders table? Define representative-owned versus Super-Admin scope,
order and action identity, responsible-representative evidence, sorting,
maximum visible pills, overflow behavior, counts, refresh events, loading and
failure behavior, and permission-safe deep links.

Material pills must open Sales Overview Inventory Needs with Create inbound
expanded. Production pills must open the affected Production assignment
surface. The client must not infer eligibility or ownership from table rows.

## Comments

> *This was generated by AI during Wayfinder issue commenting.*

**Proposed answer:** Use a dedicated bounded server projection rather than
deriving actions from visible Sales table rows.

Each action returns stable order/action identity, order number, action type,
responsible representative, qualification time, action-opened time, and a
permission-safe canonical deep link.

- Sales representatives receive only actions for orders currently assigned to
  them.
- Active Super Admins receive all unresolved actions.
- Sort by oldest action first, then order number and Material before Production.
- Return at most 50 actions with complete total and per-type counts.
- Initially display 12 pills; expose remaining results through an inline `Show
  all` disclosure.
- Refresh after payment/refund, setting, demand, inbound, assignment,
  order-revision, cancellation, and review mutations.
- Loading reserves the alert footprint. Failure shows a compact retry state
  rather than silently implying that no actions exist.
- Material deep links open Inventory → Needs with Create inbound expanded.
- Production deep links open the affected Production assignment surface.
- The destination repeats normal authorization checks; possessing a URL grants
  nothing.

**Why:** Required work remains secure, bounded, independently refreshable, and
does not add repeated evaluation to the Sales Orders list query.

**Assumptions / risk:** Fifty results is an initial safety bound and should be
measured against real unresolved volume. The prototype may adjust the
visible-pill count without changing the server contract.
