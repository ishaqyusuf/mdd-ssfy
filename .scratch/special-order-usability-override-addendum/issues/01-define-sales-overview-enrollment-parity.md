# Define Sales Overview Special Order Enrollment Parity

Type: grilling
Status: open
Blocked by: None
Parent: [`../map.md`](../map.md)

## Question

How should an eligible employee mark an existing order as a Special Order from
Sales Overview while preserving the Sales Form's enrollment audience,
customer-email prerequisite, confirmation and reason, revision initialization,
Sales Activity, query invalidation, and separate approval-request action?

## Comments

> *This was generated by AI during Wayfinder issue commenting.*

**Proposed answer:** Show **Mark as Special Order** only for orders not already
governed and employees eligible under the live enrollment audience with
`editOrders`. Reuse the canonical customer-email repair dialog, then require
confirmation and a reason. A shared server transition initializes the current
Approval Revision, moves the order to Signature Pending, preserves historical
evidence, records Sales Activity, and refreshes Sales queries. Enrollment does
not automatically send an approval request.

**Why:** Sales Overview and the Sales Form must not produce different enrollment
behavior or bypass the current pilot audience.

**Assumptions / risk:** Enrollment eligibility remains server-authoritative and
may currently resolve to Super Admin only.
