## Question

Which highest-level test seams and browser scenarios must prove Sales Overview
enrollment, immutable customer naming, mobile full-screen signing, policy/footer
and C.C.C parity, Role configuration, server-authoritative overrides, declined
state protection, ordinary permissions, and direct-bypass resistance before the
addendum can ship?

## Comments

> *This was generated by AI during Wayfinder issue commenting.*

**Proposed answer:** Validate at the highest existing seams:

- Sales Overview enrollment mutation and sheet interaction.
- Public approval response contract and responsive page behavior.
- Canonical C.C.C calculation and immutable snapshot/revision behavior.
- HTML and both PDF template renderers.
- Role configuration and generated session permissions.
- Server enforcement matrices for ordinary allow, warning, block, override,
  Customer Declined, missing underlying permission, batch/job invocation, and
  forged-client bypass.
- True mobile-viewport browser proof for rotate guidance, signing, Clear,
  Cancel, OK, reload, and successful submission.

**Why:** These seams prove customer-visible behavior and server integrity
without duplicating low-level implementation tests.

**Assumptions / risk:** Existing unrelated repository-wide typecheck failures
remain separately documented and cannot substitute for focused green
validation.
