# Define Customer Name And Mobile Signature Capture

Type: grilling
Status: open
Blocked by: None
Parent: [`../map.md`](../map.md)

## Question

How should the public approval form source and protect the displayed Customer
name, and how should small-screen users enter, clear, cancel, confirm, and
submit a drawn signature in a full-screen landscape-oriented experience without
depending on unsupported browser orientation locking?

## Comments

> *This was generated by AI during Wayfinder issue commenting.*

**Proposed answer:** Display the immutable request-snapshot customer name in a
disabled **Customer name** field. The response endpoint derives the stored name
from the request and ignores client attempts to replace it. Desktop retains
inline signing. On small screens, tapping Digital Signature opens a full-screen,
landscape-optimized modal with rotate guidance, Clear, Cancel, and OK. Cancel
preserves the previously confirmed signature; OK requires and commits a
non-empty signature. Portrait remains functional without relying on browser
orientation locking.

**Why:** This provides the requested customer-name behavior and usable mobile
signing without weakening immutable evidence.

**Assumptions / risk:** The customer name and secure-link possession do not
independently prove the legal identity of the person drawing the signature; the
existing disclosure remains.
