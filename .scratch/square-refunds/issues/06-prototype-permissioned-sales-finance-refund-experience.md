# Prototype The Permissioned Sales And Finance Refund Experience

Type: prototype
Status: closed
Blocked by: 03, 04, 05
Parent: [`../map.md`](../map.md)

## Question

What connected Sales Overview and Finance payment-detail experience should show
eligibility, provider truth, remaining refundable value, multi-order allocation,
C.C.C/tip treatment, confirmation, pending progress, completion, failure, and
Finance-review states to a user with `can.editRefundSquare`?

## Comments

> *This was generated by AI during Wayfinder issue commenting.*

**Proposed answer:** Build one shared refund-review sheet used from Sales
Overview and Finance payment detail. Render the entry action only for
`can.editRefundSquare`; enforce the same capability on every server command.

The workflow should show:

- Verified Square tender, source, masked card/device context, charge, completed
  refunds, pending reservations, and remaining refundable value.
- Refund reason and any required completed cancellation/adjustment reference.
- Full or partial amount with explicit principal, C.C.C, and tip treatment.
- Mandatory allocations for every affected Sales Order.
- Required audit evidence and a final immutable confirmation summary.
- A status timeline for submission, pending, completed, failed, rejected, and
  local application.
- Resulting order balances and any Finance exceptions without changing
  operational status.

Finance additionally receives an external-refund allocation mode. Pending
submissions are read-only and cannot be duplicated. Failed/rejected attempts
offer guided resolution, while ambiguous submissions retry the same intent
rather than creating another refund.

**Why:** This produces one consistent, permissioned operator experience across
both required surfaces.

**Assumptions / risk:** The prototype must make payment-level C.C.C/tip distinct
from order-principal allocation; combining them in one generic amount field
would reintroduce accounting ambiguity.

### Resolution

Implemented the shared permissioned transaction/refund sheet in Sales Overview
and Sales Finance, including verified tender evidence, remaining capacity,
component split, eligible-order allocation, commercial evidence, immutable
confirmation, timeline, retries, and external-refund allocation mode. Desktop
and mobile browser QA passed.
