# Define Default And Archived Filter Query Semantics

Type: grilling
Status: open
Blocked by: 01 — Define Archived Sales Order State And Lifecycle Boundaries
Parent: [`../map.md`](../map.md)

## Question

How should the canonical `sales.getOrders` and `sales.getOrdersSummary`
contracts express the default non-archived scope and `Show > Archived` scope
while preserving combinations with existing filters, saved tabs, exports,
Sales Bin, pagination, and legacy/projected read parity?

## Comments

> *This was generated by AI during Wayfinder issue commenting.*

**Proposed answer:** Add an explicit archive scope whose absent/default value
means `archivedAt IS NULL`; `Show > Archived` means non-deleted orders where
`archivedAt IS NOT NULL`. Keep the scope composable with search, date, customer,
status, Special Order, saved tabs, sorting, and export filters. Present Archived
under the visible `Show` filter and label the existing Special Order scope
separately to avoid duplicate Show controls. Apply the scope before counting
and pagination in list, summary, payment-review fallback, and projected-read ID
selection. Sales Bin remains deletion-only and ignores archive scope. Shared
mobile queries inherit the default exclusion, but mobile archive controls and
an Archived filter are out of scope.

**Why:** One canonical scope prevents list, summary, saved-tab count, export,
legacy, and projected-read drift.

**Assumptions / risk:** Archived and Special Order filters must remain
independently combinable.
