## Question

Where should users archive and restore Sales Orders, should single-row and
selected-row actions both be supported, what confirmation and partial-success
behavior is required, and which existing permission should authorize each
command?

## Comments

> *This was generated by AI during Wayfinder issue commenting.*

**Proposed answer:** Add `Archive` to normal row actions and `Restore` to rows
under `Show > Archived`. Support the same operations for selected rows. Reuse
`editOrders`; no new permission is needed. Confirm every archive, strengthening
the message when any selected order is non-terminal. Commands are idempotent,
capped at 100 unique orders, recheck current state server-side, and report
changed and skipped orders without failing the whole batch for harmless stale
selections. Record each transition in Sales History with action, actor, and
timestamp.

**Why:** Row and batch controls address everyday cleanup while preserving
authorization, attribution, and safe retries.

**Assumptions / risk:** Archive reasons are not required for the first version;
Sales History provides durable attribution.
