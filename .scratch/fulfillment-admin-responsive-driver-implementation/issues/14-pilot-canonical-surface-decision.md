# 14 — Run The Pilot And Publish The Canonical-Surface Decision

**Source:** [Fulfillment Admin And Responsive Driver Workflow](../../dispatch-admin-responsive-driver-workflow/spec.md)

**What to build:** Run the authorized bounded pilot, assemble browser/device,
operations, reliability, permission, reconciliation, and fallback evidence, and
record the explicit decision whether responsive web may become canonical. The
outcome either amends the current ADR and defines a later compatibility cutover
or keeps Expo canonical with unresolved gaps documented.

**Blocked by:** 13 — Add Cohort Rollout, Telemetry, And Rollback Controls.

**Status:** ready-for-agent

- [ ] The authorized pilot cohort, duration, operators, supported devices, acceptance thresholds, and stop conditions are recorded before enablement.
- [ ] Evidence covers assigned-work parity, packing, blocker response, notifications, weak networks, proof completion, permissions, accessibility, fallback use, support feedback, and inventory reconciliation.
- [ ] No open high-severity correctness or authorization defect is waived for cutover.
- [ ] A rollback drill confirms completed operational truth survives interface restoration.
- [ ] The decision explicitly either retains Expo as canonical or publishes an approved ADR amending canonical ownership and defining subsequent route-retirement gates.
- [ ] Packing List and compatibility surfaces are not removed merely because the pilot completes; every retirement remains a separate explicit decision.
- [ ] Brain, feature, route, permission, API, database, and rollout documentation reflect the evidence-backed outcome.
